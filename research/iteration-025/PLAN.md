## WHAT STANDS (read before judging the rows)
- THE RECORDER IS THE KIT'S (`lab/mir/render/recorder.js`, six laws): frame zero is the play edge, every frame moves musical time by exactly 1/fps (`render/clock.js`), the modulation is driven by that clock (HAZARD `modulation`: 'drive'), the encoder is proven before the run, nothing is lost to a failure (the OPFS store, RECOVER · RESUME). λWAVES hands it `frame(i, ctx)` (`lab/render-exact.js` `createFilm`): the field read back at the frame's t under THE TIME LAW, twelve HAZARDS pinned and witnessed, a digest per frame, `recording.json` beside the frames.
- THE MP4 IS VIDEO ONLY (`render/mp4.js`: one avc1 trak, faststart, ctts + elst for B-frames). The AUDIO CLIP (`timeline/audio-kind.js`, `audio-analysis.js`): a dropped file decoded once, analysed into 100-Hz envelopes (LEVEL · LOW · MID · HIGH through the model's own follower), stored by content hash, its `value(beat)` a LOOKUP — so a recorder renders the modulation it drives exactly, with no analyser latency; KEEP AUDIO plays the file by the transport's beat (`audio-playback.js`, varispeed clip.scale · bpm / source.bpm, 200 ms lookahead) and is MUTED while a recorder owns the clock ("it records no audio"). The recorder refuses only a LIVE audio source (the microphone device, `recorder.js:212`).
- THE FILM IS NOT THE SCREEN: `frame()` reads the field only — no NODES chain (019's "RENDER bakes the graph" was a later row), no LAYER or SHADER node, no 2-D overlay (`#particles` etc., HAZARD `overlays`), no stage words, no ESP bar. A screen recording has all of them: this is the gap Josh feels as "render setting disobedience".
- THE WORKFLOW: the RENDER card (`lab/film-card.js` over the kit's `createRenderCard`, closed on the right rack) is the only door; FILE has no RENDER row (`lab/shell/notebook.js:85`, the 021 tree of ACTIONS); the TIMELINE window has no door to it.

## THE LAW OF 025 (to docs/laws/film.md at the close)
- THE BOUNCE (Josh 10-28): a render is a DAW's bounce — the arrangement rendered at its own clock, sample- and frame-exact, never a recording of the screen. THE AUDIO IS ON THE FILM: the KEEP clips in the range are mixed offline at the same beats the frames read and muxed into the MP4 (or a WAV beside PNG frames); frame 0 and audio sample 0 are the same instant, the play edge. THE FILM IS THE SCREEN: the frame carries the NODES chain, the layers, the shader node and the overlays the screen shows, each deterministic or declared out by name in the honest report. EVERY SETTING IS A WITNESS: a render reports each option beside what the file holds.

## CHAINS (one Opus builder each, one at a time, each on the merged tree; MERGE ORDER A → B → C)
### A — THE AUDIO (kit MIR 1.5.6-alpha.12+, the clone road; every row additive; adopt back; pin; bundle)
A1 THE AUDIO TRACK IN THE MUXER: `render/mp4.js` takes `audio: { codec: 'mp4a.40.2' | 'opus', sampleRate, channels, description, samples: [{ data, ts, dur }] }` and writes a second trak (`mp4a` + `esds` from the encoder's `decoderConfig.description`, or `Opus` + `dOps`), its own timescale = sampleRate, chunks interleaved with the video by time, `stts/stsc/stsz/stco` for both, the encoder's priming (AAC ≈ 1024–2112 samples by machine, Opus pre-skip from `OpusHead` bytes 10–11, typically 312 — RESEARCH.md §2) as the audio trak's `elst` media_time AND an `sgpd/sbgp` roll group (players need both), so sample 0 of audible audio sits at video frame 0; `stts` derived from integer indices (audio timescale = sampleRate, video = the fps fraction), never from µs, `mvhd` duration = the longer trak. Pure; `mp4Parse` reads it; a node test in the clone (`npm test`) proves the boxes.
A2 THE MIXDOWN: `render/audio-mix.js` (new, pure where it can be): the KEEP clips in the range → `OfflineAudioContext(2, N, 48000)`, each clip a buffer source placed by the SAME pure placement the live path uses (`audioPlacement(clip, curve, beat, bpm)` → rate, offset) with the range's start as sample 0, N = round(frames · 48000 / fps) exactly; gain as live (no limiter, no normalise: the levels are the arrangement's); → planar Float32 channels. No clip in range → no audio track (the result says so).
A3 THE ENCODE: `render/encoder.js` grows an audio sink: `AudioEncoder` down a ladder (`mp4a.40.2` 48 k → `opus` at 48 k; `isConfigSupported` — RESEARCH.md §2: AAC is absent in Firefox and in every browser on Linux, so Josh's files will be Opus-in-MP4; the ladder is still asked, never assumed); the priming measured once per machine by an impulse encoded and decoded (memoised as `verifyEncoder` is) and handed to the muxer, AudioData timestamps = integer µs from the sample index (never float seconds), chunks stored beside the video chunks (the store's checkpoint carries them, RESUME rebuilds), a `verifyAudioEncoder` preflight (two chunks, as the video's); PNG FRAMES → `<name>.wav` (16-bit PCM, N samples exactly) in the frames zip. Back-pressure as the video's.
A4 THE PANEL, THE RESULT, THE REFUSAL: the render panel's AUDIO row — ON · OFF (ON by default when a KEEP clip is in the range; the row names the clips and the codec it will use; OFF or no clip = the old file); the result carries `audio: { codec, sampleRate, samples, clips, durationS }` and the manifest records it; the refusal stays for a LIVE source only, its sentence now "Record the microphone to a file first (● REC), or switch the device off."; `audio-playback.js`'s busy-mute unchanged (the mixdown is offline).
A5 THE ALIGNMENT PROOF (a self-test stage, `render/selftest.js`): a synthetic click clip (clicks at beats 0 · 1 · 2, 120 BPM) rendered 2 s at 30 fps through the kit's own path; the MP4 parsed: the audio trak's edit list, the first audible sample's time, each click's sample index against its beat's frame index — agree within one sample; one line in RUN SELF-TEST.
A6 ● REC (if it fits in ≤ 120 kit lines; else a FOR-MIR line): the modulation's AUDIO device gets ● REC (beside MIC): press → the live input is recorded (`MediaRecorder` on the capture's own track; the context's `outputLatency` noted) from the beat the press lands on; press again → the recording becomes an audio clip through `audioClipFromFile` (KEEP, on the device's lane at that beat, named REC-n). THE PRIVACY LAW 4 amended: "nothing is recorded, stored or sent WITHOUT ● REC; a recording is a file in the project and nowhere else." Josh's "recorded in".
Kit laws: words through `label()`/`t()` + the English pack; version sites 3/3, a CHANGELOG line per door, `npm test` in the clone; adopt, pin, `--check`; the bundle `.tmp/kit-1.5.6-alpha.N.bundle` with its absolute path in A-BUILD.md.

### B — THE FILM IS THE SCREEN (`lab/render-exact.js`, `lab/film-card.js`, NODES, the overlays)
