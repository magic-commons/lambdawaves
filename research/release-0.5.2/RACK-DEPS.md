## 12. What the walker cannot see

- **Dynamic property names** — `ui[k]`, `LW[x]`, `obj[name]`: counted per section as dynamic accesses, never attributed to a member.
- **Aliases** — `const u = ui; u.x = 1` writes `ui.x` invisibly; a bag destructured (`const { a } = ui`) reads `ui` whole.
- **Bags passed whole** — `reworkNative({ ui, … })`, `createX({ … })`: the module's own reads and writes of the object are outside this file (§5 names the lines).
- **Calls are reads** — calling a boot function that assigns shared state is a read of the function; there is no call-graph closure, so a section's TRANSITIVE writes are not counted.
- **`this`, `arguments`, `eval`, `with`** — not modelled; inside boot's body: `this` ×0, `arguments` ×0, `eval(` ×0, `with (` ×0.
- **Deferred is lexical** — a reference inside any nested function counts as deferred, including a callback boot invokes while it runs (`forEach`, an IIFE, a constructor that calls back at once); such a forward use is really eager.  The TDZ column of §10 is exact only for references at boot's own statement level.
- **Destructured renames** — `const { hand: modHand } = mod` declares `modHand` and reads `mod`, as JavaScript does; the link from `modHand` back to `mod.hand` is not kept.
- **ASI** — statement ends are `;`, a closing bracket, or a NAME on a new line after a token that ends an expression; a file that leans on other ASI shapes could mis-scope a for-loop body or an arrow's expression body.
- **Classes** — not modelled (rack.js has none; a class would raise a walker warning).
- **Shadowing — how far it goes**: function parameters (plain, defaulted, destructured, rest), arrow parameters, inner `const` / `let` / `function` / `var` per block, for-heads (also over an unbraced body), catch bindings and named function expressions all shadow, and resolution uses the WHOLE block (a later inner `const x` shadows `x` from the block's first line, as the TDZ does).  An arrow's expression body inside a ternary branch extends to the next `,` / `;`, so a second arrow in the other branch sees the first one's parameters (harmless unless they share a boot-level name).
- Shadowing measured: 233 references resolved to an inner binding that shares a boot-level name — `S` ×49, `cards` ×3, `esc` ×6, `id` ×114, `keep` ×7, `obs` ×4, `q` ×26, `rack` ×2, `rk` ×13, `states` ×1, `stats` ×6, `tick` ×2.
