## THE ROUTE (what "route… something" should mean here)
A compositor's power is the branch: blur a copy, mix it back (a glow); threshold a copy, use it as a mask (grade the highlights only). The honest way in Houdini/Blender is a DAG with wires the user draws, two-input nodes (MIX, MASK) and reroute dots. λWAVES' graph is a column that compiles to ONE SVG filter; an SVG filter is itself a DAG (`in`/`in2`/`result` on every primitive), so a DAG is compilable — but it costs the order law (a card's y no longer says where it runs), a wire editor (port drag, hit-test, detach, reroute), a topological compiler, a kit change for named run results, and a second view (the rack column) that cannot show a DAG. Roughly doubling NODES for a power most readers will never wire.

**The λWAVES flavour instead: every node carries FADE and MASK** (After Effects' effect opacity and mask, Blender's Fac socket, Nuke's mix/mask knobs) — the two things a branch is for, without a branch:
- **FADE** (0–100 %): the node's output mixed back with its input. For a TABLE node this folds into its own table for free (y′ = y + a·(f(y) − y)); for a MATRIX node into its own matrix for free (M′ = (1 − a)·I + a·M); for a PRIMITIVE it is one `feComposite` (arithmetic k2 = a, k3 = 1 − a) on the pass it already pays; for a LAYER it is the layer's opacity (already AMOUNT).
- **MASK** (NONE · LIGHTS · DARKS · MIDS · CENTRE · EDGES, with SOFT): where the node applies. A luma mask (LIGHTS/DARKS/MIDS) = luma matrix → a soft-threshold table → the node's result composited through it (`feComposite in=… in2=mask operator=arithmetic`, or `feMerge` of masked and unmasked); a shape mask (CENTRE/EDGES) = a radial `feImage`-free gradient drawn as `feFlood`+`feComponentTransfer` on a y/x ramp is not available in SVG filters, so CENTRE/EDGES use the LAYER host's radial mask image through `feImage` with a data URI of a tiny radial PNG scaled by `preserveAspectRatio` — or simpler and exact: `feTurbulence` is wrong, so the builder draws the radial gradient once on a 64 × 64 canvas (as the grain tile is drawn once) and hands it as `feImage href=data:` — one image per distinct mask, cached. A masked node is a pass (the cost mark says ···); the mask image is shared by every node that asks for the same one.
- The compiler: a node with MASK ends the run it would have folded into and emits its own run as prim markup with `result`/`in` names (prim markup is generic SVG: NO kit change). The order law stands: the column is the chain.
This gives "grade the highlights only", "posterize the centre", "blur the edges", "sharpen 40 %" — the branch's whole use — with one knob and one picker per node. A true DAG (MIX of two branches, reroute dots) stays a LATER ROW in the plan, with the kit's `setChain` growing named results, if Josh wants it after living with FADE/MASK.

The PREVIEW strip: every TABLE and MATRIX card draws a 2-row ramp (a grey ramp and a hue ramp, 128 × 10 canvas) through the node's OWN transfer — what this node alone does — redrawn when its values move (the compiler's `fn`/`matrix` on 128 samples; trivial); PRIMITIVE and LAYER cards show no strip (their effect is spatial). Copernicus embeds the node's output thumbnail; ours is the node's transfer — exact and free. The RIGHT-CLICK menu on a card (the kit's menu, as the rack windows'): VIEW HERE · SOLO · BYPASS · COLLAPSE · DUPLICATE · RENAME · RESET (home values) · MOVE UP · MOVE DOWN · REMOVE; on the ground: ADD… · FIT · TIDY · COLLAPSE ALL / EXPAND ALL · BYPASS ALL. TIDY (Houdini L): the cards in one column, SPAN-centred, GAP apart, in list order; the column view already is that.
**X3 THE FLAGS.** VIEW HERE (the display flag; an eye on every bar, one lit at a time): the stage shows the chain up to and including this node; the foot says "viewing 3 of 6"; a click on the lit eye returns to STAGE OUT; the compiler takes `upTo`. SOLO (S on a selected card; in the menu): this node alone, the rest bypassed in the picture but not in their records (a second lit mark, as a mixer's SOLO); off = the chain as before. BYPASS ALL (the graph's master ×, at the ground's head; the key \ on the ground): the A/B for a recording — the picture with and without the graph; the foot says "graph off". None of the three writes the record's bypass bits; VIEW/SOLO are the view's (session), BYPASS ALL is kept in the record (`off: true`) so a reload shows what the reader saw.
**X4 FADE AND MASK** (THE ROUTE above): FADE (0–100 %, home 100) and MASK (NONE · LIGHTS · DARKS · MIDS · CENTRE · EDGES) + SOFT (0–1) in a foot fold on every card except LAYER (whose AMOUNT is its fade; its mask is a later row); FADE and SOFT are knobs and so modulation targets (`nodes.<node>.fade`, `.soft`); the compiler folds FADE for TABLE/MATRIX, composites a PRIMITIVE's, and turns a masked node into its own run (prim markup with `result`/`in`; the mask images cached by kind + soft). The cost mark follows (a masked LEVELS reads ···). Shipped graphs may use it (FILM: VIGNETTE stays a layer; PRINT: CONTRAST masked MIDS at 60 %?) — the builder's recipes.
**Later rows (not this chain):** a true DAG (MIX of two branches, reroute dots, the kit's `setChain` with named results); LAYER masks; the governor's bypass of heavy nodes; RENDER bakes the graph; PROJECT scope for the graph.

## The laws this adds (CLAUDE.md at 020)
- THE COLUMN IS THE CHAIN: a card's place is its order; FADE and MASK are what a branch is for, so the graph stays a column (a DAG is a later row, not a drift).
- A FLAG IS NOT A RECORD: VIEW HERE and SOLO are the view's and die with the session; BYPASS (×) and BYPASS ALL are the record's.
- THE KEYS ARE THE GROUND'S: NODES' keys fire only with the ground focused and never reach the kit's one key table.
- A PREVIEW IS THE NODE'S OWN TRANSFER, drawn from the same function the compiler folds — never a second render.
- THE DEFAULT GRAPH IS EMPTY and says so in one faint line.
