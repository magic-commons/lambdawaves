## The shape (the law of this cut)
THE CATALOGUE is ONE table in `lab/catalogue.js` of every SYSTEM the instrument plays — hydrogen and its situations, the closed-form operators, ATOM,
QUARKONIUM, the molecules (live, 6-31+G*, the records, the open shells, LDA), the registers, RT, FLOW, the readout theorems, LATTICE and TUNNEL, the demos — one
row each: `{ id, name, shelf, opens, word, oracle: { test, what }, since }`, where `word` is `lab/status.js`' grammar (EXACT · NUMERICAL · UNCHECKED) and
`oracle.test` names a file in `tests/`. The table is GENERATED by `tools/catalogue-table.mjs` from the live tables where they exist (`hamiltonian.js`
HAMILTONIANS, `molecules.js` MOLECULES + RECORD_ONLY with `library.json`'s `status.energy` → the word, `lattice-model.js` PRESETS, `state.js` PRESETS for
the situations, `project-store.js` STARTERS) plus one hand table in the tool for the rows no table holds (the registers, RT, FLOW, WIGNER, RADIATION, KEPLER
… — SYSTEMS.md §1's rows, their words from its ORACLE · STATUS column), and `--check` holds the file byte-exact as `orbital-library --check` does. It is the
spine every picker reads and the paper's table; nothing in it is a claim the tree does not already make. "Every system in one picker": SPECTRUM › OPERATOR
becomes the catalogue's operator shelf with each row's status word, and a system that is a window (MOLECULES, LATTICE) opens from the same picker. "The
library in shelves": MOLECULES' SECTION press opens THE SHELF — the section's molecules as tiles you can read before you pick (name, formula, size, status
word, the installed lamp), the periodic table as the first shelf.
