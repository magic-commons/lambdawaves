# Sol's brief — "The senior-engineer stack for Magic Commons" (research and repository review, 2026-10-25; relayed by Josh, saved by Claude Yan)

Sol (GPT, the other lab) reviewed the connected repositories (λWAVES, MIR; NEBULA, BASINS and AUTOMATA by their documentation only) and the public app.
Its thesis: the next improvement is not a smarter agent but a senior developer's working environment for the agents already here — a code navigator,
current references, a real browser debugger, independent checks — reinforcing the discipline the repos already have (physics tests, browser acceptance
tests, GPU pixel digests, MIR's parity tools and ANTI-PATTERNS.md) rather than replacing it with templates.

## The MCPs it ranks (for these projects, not a popularity table)
| # | MCP | main improvement | when |
|---|---|---|---|
| 1 | Serena | semantic code navigation, cross-file refactoring (JS, TS, WGSL) | architecture and cleanup |
| 2 | Chrome DevTools MCP | browser profiling, runtime failures, rendering performance | performance and debugging |
| 3 | Context7 | current, version-specific API docs (CLI + Skills mode is leaner) | research and implementation |
| 4 | Playwright | real interaction testing (Microsoft now recommends CLI + Skills for scripted checks; MCP for exploratory) | UI, regression |
| 5 | GitHub MCP | history, issues, PR review | integration and release |
| 6 | Semgrep | static security analysis | audit and release |

Starting combination: Serena + Context7, with Chrome DevTools or Playwright only when a task needs a browser. Too many simultaneous MCPs cost context
and tool-selection overhead (community reports, not controlled evidence). WebGPU Inspector (a browser extension, not an MCP) is the GPU-side companion;
a Chrome trace certifies nothing on Safari or Firefox.

## The cleanup tools (CLIs first)
knip (+ its MCP for configuration) — unused files, exports, dependencies; dependency-cruiser — import boundaries, cycles, graphs; ast-grep — syntax
patterns, duplicated implementations; Semgrep — security. For λWAVES, knip needs care: static HTML entry points, dynamic initialisation, a service
worker, adopted MIR modules and test utilities. THE RULE: prove something is dead before deleting it; an unused-code report is an investigation queue,
not a deletion order.

## The passes
| pass | objective | tools | output |
|---|---|---|---|
| 1 reconnaissance | understand the change and the code | Serena, native search | change plan, affected modules |
| 2 architecture | boundaries, reuse, coupling | Serena, dependency-cruiser | minimal design |
| 3 implementation | the smallest correct change | Context7 only when APIs require it | code and focused tests |
| 4 refactor | remove unnecessary code and duplication | Serena, knip, ast-grep | smaller, clearer implementation |
| 5 runtime QA | real interactions, rendering profile | Playwright or Chrome DevTools | reproducible evidence |
| 6 release | security, compatibility, deployment | Semgrep, GitHub, existing gates | release readiness report |

Keep the architecture pass separate from the polish pass; an implementation agent does not use every MCP because it can; a reviewer does not rewrite
before understanding why the original was designed that way.

## Token policy
Routine tasks on native search, editing, shell and focused tests; Serena only when symbols and cross-file relations matter; narrow documentation
lookups; targeted browser observations over full-page snapshots; short task-specific skills over always-loaded instructions; compact test results,
full logs by reference. Progressive tool discovery over loading every tool description upfront.

## The proposed engineering contract (one rule set for Claude, Codex and later agents)
1. Preserve behaviour unless the task explicitly changes it. 2. Reuse MIR's actual components, not copied imitations. 3. Keep simulation, rendering,
UI and persistence boundaries explicit. 4. No dead controls, duplicated state or speculative abstractions. 5. Fix defects at their source, not by
local workarounds. 6. Require proofs for refactors and measurements for optimisations. 7. Keep documentation, tests and error handling proportional
to the task. 8. Plain, precise language in UI and documentation. 9. Report what was verified, not merely what was changed. 10. Prefer fewer, clearer
modules when behaviour is equivalent. — To complement CLAUDE.md, NOTES-FOR-AGENTS, the MIR contracts and anti-patterns, not to compete with them.

Three slops: CODE slop (duplicated utilities, wrappers, defensive excess, hidden side effects, sprawling controllers — Serena, knip, ast-grep,
architecture rules); INTERFACE slop (decorative UI, inconsistent gestures, meaningless controls, visual drift — MIR is the defence; add browser
inspection and visual regression); LANGUAGE slop (verbose labels, vague explanations, marketing phrases — an editorial skill and a human pass).
λWAVES' control words (SPECTRUM, PALETTE, IMPULSE, WAVE) are the model to carry into the other apps.

## App priorities
λWAVES — performance and safe change: Serena for navigation, Chrome DevTools for profiling; preserve the physics oracles, the digest lock, the browser
tests and the PWA checks; eliminate architecture debt without changing numerical results or the instrument's feel. MIR — design-system integrity:
dependency-cruiser and knip; stop consumers growing private versions of MIR components; expand the parity tests as skins and controls gain states.
NEBULA / BASINS — renderer–UI separation (evaluation, colouring, modulation, viewport as independent boundaries). AUTOMATA — simulation contracts
(rule data, operator compilation, CPU/GPU execution, scheduling, rendering); deterministic references before optimising WGSL kernels. MIR is the
common interface language, never a reason to force the engines into one runtime.

## How it would start
A controlled pilot on λWAVES, not a global install. Serena: `uv tool install -p 3.13 serena-agent` · `serena init` (the project warns against stale
marketplace recipes). Context7: `npx ctx7 setup`, CLI + Skills first. Chrome DevTools: `claude mcp add chrome-devtools --scope user npx
chrome-devtools-mcp@latest`. knip: `npx @knip/mcp`, entry points configured before trusting findings. Then ONE representative refactor with and
without Serena (time, tool calls, tokens, missed references, tests passing) and one UI task Playwright CLI vs MCP.

## The development-pass prompt
"Objective: reduce complexity while preserving behaviour, not maximise the size of a diff. Establish the current behaviour and relevant contracts.
Identify unnecessary complexity, duplicated logic, unclear ownership and potential regressions. Implement only justified changes. Preserve simulation
outputs, state compatibility and UI behaviour. Run focused tests and existing release gates. Report exactly what was simplified and what evidence
supports the result."

Sol's first move: a Serena + dependency-cruiser + knip audit of λWAVES and MIR, no edits during inspection, then rank changes by benefit instead of a
giant rewrite. — Claude Yan's reading of this brief against the repo is `PLAN.md`; the measured audit is `AUDIT.md`.
