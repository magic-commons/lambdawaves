# λWAVES on Android: the TWA proof (P06)

**The question:** does λWAVES run full-screen with WebGPU as an installable Android app? The shell is a
**Trusted Web Activity (TWA)**: a tiny Android app that opens https://lambdawaves.magic-commons.com/ in the
phone's Chrome, full-screen. Chrome is used, not Android WebView, because Chrome enables WebGPU on
Android 12+ (Qualcomm/ARM GPUs) and WebView does not. Generated by Bubblewrap 1.25.0.

| file | status | what it is |
|---|---|---|
| `twa-manifest.json` | **source**, tracked | the one input Bubblewrap reads: package id, host, name, colours, icons, signing key path, version |
| `assetlinks.json` | **source**, tracked, public | the Digital Asset Links statement; must be served at `/.well-known/assetlinks.json` |
| `build.sh` | **source**, tracked | regenerate the project + build signed APK/AAB into `out/` + check the fingerprint |
| `README.md`, `.gitignore` | **source**, tracked | this runbook; the ignore list (everything else here is ignored) |
| `app/ gradle/ build.gradle settings.gradle gradle.properties gradlew* store_icon.png manifest-checksum.txt` | generated, ignored | the Android project; `bubblewrap update` deletes and rewrites it from `twa-manifest.json` |
| `app-release-*.apk`, `app-release-bundle.aab`, `.gradle/`, `app/build/` | generated, ignored | build outputs and caches |
| `out/app-release-signed.apk`, `out/app-release-bundle.aab` | generated, ignored | the copies to install / upload |
| `local/upload.keystore`, `local/KEYSTORE-PASSWORD.txt` | **secret**, ignored | the upload key and its password. **Back both up** (password manager + one offline copy) |

## 1 · Build (Linux build host; Node 22; no Java or Android SDK needed beforehand)

**1.1 Tooling, once.** Bubblewrap is run with `npx`, never installed globally. Its first run asks three
questions (install JDK 17? install the Android SDK? accept the SDK terms?). Answer yes to all:

```sh
yes | npx --yes @bubblewrap/cli@1.25.0 doctor   # JDK 17.0.11 + SDK into ~/.bubblewrap (1.7 GB after the first build); ends "Your jdkpath and androidSdkPath are valid."
```
`~/.bubblewrap/config.json` then holds `jdkPath` and `androidSdkPath`. The first `build` also installs
build-tools 36.1.0 (and platform-tools, i.e. `adb`) through sdkmanager, which asks for a licence: run that
first build as `yes | ./build.sh`. Gradle's own cache goes to `~/.gradle`.

**1.2 The upload key, ONCE (never regenerate it after the first Play upload):**

```sh
cd shells/android && mkdir -p local && chmod 700 local && umask 077
PW="$(head -c 256 /dev/urandom | tr -dc 'A-Za-z0-9' | head -c 24)"; printf '%s\n' "$PW" > local/KEYSTORE-PASSWORD.txt
~/.bubblewrap/jdk/jdk-17.0.11+9/bin/keytool -genkeypair -v -keystore local/upload.keystore -storetype PKCS12 \
  -alias lambdawaves-upload -keyalg RSA -keysize 2048 -validity 10000 -storepass "$PW" -keypass "$PW" \
  -dname "CN=Joshua Hosain, O=Magic Commons, C=US"
```
Play App Signing means Google holds the real app-signing key; this is only the *upload* key, and Play
Console can reset a lost or compromised upload key (Setup ▸ App signing ▸ request upload key reset). So a
generated key is fine for the proof.

**1.3 Build (every time):** `./build.sh` (~1 min after the first). The 2026-09-24 build: APK 1,048,750 B,
AAB 1,171,294 B, versionCode 1, versionName "1", minSdk 21, targetSdk 36, compileSdk 36, label `λWAVES`
(the non-ASCII name builds fine). It runs exactly this:

```sh
export BUBBLEWRAP_KEYSTORE_PASSWORD="$(cat local/KEYSTORE-PASSWORD.txt)" BUBBLEWRAP_KEY_PASSWORD="$BUBBLEWRAP_KEYSTORE_PASSWORD"
npx --yes @bubblewrap/cli@1.25.0 update --skipVersionUpgrade   # twa-manifest.json → Android project + manifest-checksum.txt, no prompts
npx --yes @bubblewrap/cli@1.25.0 build                         # no prompt: checksum matches, passwords come from the env
cp -f app-release-signed.apk app-release-bundle.aab out/
```
Without `update` first, `build` finds no `manifest-checksum.txt`, asks to regenerate, and also bumps the
version (and asks for a version name). **To ship a new shell version:** raise `appVersionCode` (and
`appVersionName`/`appVersion`, which Bubblewrap reads) in `twa-manifest.json`, then `./build.sh`.
`bubblewrap init` was not used (it is an interactive questionnaire); `twa-manifest.json` was written by hand
in its schema.

**1.4 Fingerprint → assetlinks.json.** `keytool -list -v -keystore local/upload.keystore -alias lambdawaves-upload`
prints `SHA256: 10:9E:…:29`; that value is in `assetlinks.json` and in `twa-manifest.json` `fingerprints`.
`build.sh` refuses to finish if they differ. **After the first Play upload**, Play re-signs the app with
*Google's* key: copy Play Console ▸ Test and release ▸ App integrity ▸ App signing ▸ *App signing key
certificate* SHA-256 into `assetlinks.json` as a **second** entry in `sha256_cert_fingerprints` (keep the upload
key for sideloaded builds) and redeploy the site. Without it, the Play-installed app shows the URL bar.

## 2 · The phone, before installing anything

1. Android **12 or newer** (Settings ▸ About phone ▸ Android version).
2. Chrome **121 or newer**: Play Store ▸ Chrome ▸ Update. Make Chrome the **default browser** for the test
   (Settings ▸ Apps ▸ Default apps ▸ Browser app). A TWA opens in the default browser if that browser supports TWAs
   (Samsung Internet does), and only Chrome is known to have WebGPU here.
3. In Chrome open `chrome://gpu` and find **WebGPU: Hardware accelerated**. If it says disabled or software, stop:
   write the row with verdict FAILS (no WebGPU) and the GPU name from that page.
4. In Chrome open https://lambdawaves.magic-commons.com/ and let it run once. The field must draw in Chrome
   before the app can draw it. This visit also installs the service worker the app will use offline.

## 3 · Install the APK

- **By USB:** on the phone, Settings ▸ About phone ▸ tap *Build number* 7× ▸ Developer options ▸ **USB debugging** on.
  Then on Linux: `~/.bubblewrap/android_sdk/platform-tools/adb install -r shells/android/out/app-release-signed.apk`
  (or `npx --yes @bubblewrap/cli@1.25.0 install --apkFile=out/app-release-signed.apk` from `shells/android`).
- **Without a cable:** copy `app-release-signed.apk` to the phone (Drive, USB, email), open it in Files, and allow
  *Install unknown apps* for Files when Android asks (Settings ▸ Apps ▸ Files ▸ Install unknown apps).
- USB debugging also gives you a console: desktop Chrome ▸ `chrome://inspect` ▸ the phone's λWAVES page ▸ inspect.
  Type `__LW.clock.t`, `__e`.

## 4 · What you should see

- **Before** `/.well-known/assetlinks.json` is live (2026-09-24: a 404; it ships with a site deploy once
  `tools/build-deploy.mjs` copies this folder's `assetlinks.json` into `dist/.well-known/`, the lead's call): the app opens with a **Chrome
  custom-tab bar** at the top (the site's title and URL, an ✕). That is expected. It means Chrome could not
  verify that the site trusts this app, so it shows the address.
- **After** it is live with this fingerprint: **full-screen, no bar**. If the bar remains after the file is live,
  force-stop the app (long-press icon ▸ App info ▸ Force stop), or clear its storage, and relaunch. Chrome checks
  again at launch.
- Check the file from any browser: https://lambdawaves.magic-commons.com/.well-known/assetlinks.json must
  show the JSON (Content-Type `application/json`, no redirect). Google's checker:
  `https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://lambdawaves.magic-commons.com&relation=delegate_permission/common.handle_all_urls`

## 7 · Google Play (when the proof passes)

- **Account:** Play Console developer account, **$25 one-time**, with identity verification (ID document; the
  account's legal name and address). An *organization* account needs a D-U-N-S number but skips the rule below.
- **Personal accounts created after 2023-11-13** must run a **closed test with at least 12 testers opted in
  continuously for at least 14 days** before they can apply for production access. Then apply
  (Dashboard ▸ Apply for production); the review "usually takes seven days or less, but can occasionally take
  longer". Source: https://support.google.com/googleplay/android-developer/answer/14151465
  So the earliest public release is **about 3 weeks after the closed test starts**. Recruit the 12 testers first
  (their Google accounts go into the closed-test email list; each must opt in via the link and install).
- **Upload:** `out/app-release-bundle.aab` (Play requires an AAB, not the APK). Enrol in Play App Signing (default),
  then add Google's app-signing SHA-256 to `assetlinks.json` (§1.4).
- **Data safety form:** no data collected or shared. The microphone is used on the device only, when the user
  turns on audio input, and nothing leaves the device. No account, no analytics.
  (The TWA manifest does not request the microphone permission; Chrome asks for it.)
- **Privacy policy URL:** required. Publish a short page on magic-commons.com that says the above.
- **Content rating questionnaire** (IARC): answer it; educational/science, no user interaction features. The
  photosensitivity warning is worth mentioning in the description.
- **Target API level:** read 2026-09-24 at https://support.google.com/googleplay/android-developer/answer/11926878:
  *"Starting August 31, 2026: New apps and app updates must target Android 16 (API level 36) or higher"*
  (extension to 2026-11-01 on request). This build: **targetSdkVersion 36, compileSdkVersion 36** (Bubblewrap
  1.25.0 template): **meets it.** minSdkVersion is 21 (Bubblewrap's default). WebGPU itself needs Android 12
  (API 31): raising `minSdkVersion` to 31 in `twa-manifest.json` would keep the Play listing off phones that
  cannot draw the field. That is Josh's call before the store build.

## 8 · The update model

- The app **is** the website. A site deploy (`tools/build-deploy.mjs` + wrangler) reaches every installed app on its
  next launch, through the same service-worker update path as a browser tab. No Play submission.
- A Play submission is needed **only when the shell changes**: name, icons, colours, splash, package settings,
  target API level, or `minSdkVersion`. Bump `appVersionCode`, `./build.sh`, upload the new AAB.
- Changing the icon or name on the site's `manifest.webmanifest` does not change the installed app until the shell is rebuilt.

## 9 · What the TWA does not do

- **No bundled copy of the app.** The APK holds only the launcher, splash and icons. The **first launch needs
  the network** once (to fetch the site and install the service worker); after that it runs offline.
- **No native bridges:** nothing beyond what Chrome gives any web page. No notifications (disabled), no
  background work, no Android file APIs; downloads and the file chooser are Chrome's.
- **No WebGPU without Chrome.** If Chrome is missing or disabled, the TWA falls back to a Custom Tab in another
  browser, which may lack WebGPU. The WebGPU check is `chrome://gpu`, per phone.
