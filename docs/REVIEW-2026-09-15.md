# Repository review · 2026-09-15

This pass focused on input correctness, repository structure and avoiding redundant
work during gestures. It used the project's contribution/UI rules and the
[Thermo-Nuclear Code Quality Review guidance](https://github.com/cursor/plugins/blob/main/cursor-team-kit/skills/thermo-nuclear-code-quality-review/SKILL.md).
Assisted by OpenAI Codex.

## Fixed and reproduced

The new browser regression suite failed on all six of these cases before the fixes:

| Trigger | Previous behavior | Corrected behavior |
| --- | --- | --- |
| Another pointer moves/releases during an impulse | It changed the impulse and released it | Only the initiating pointer controls the action |
| Browser cancels an impulse | A physics job ran and changed the register | Cancellation removes the preview without applying it |
| Stage loses pointer capture | Camera remained marked as dragging | The gesture ends without a fling |
| Secondary mouse button drag | Rotated the camera | Stage dragging starts with the primary button |
| Mouse reports wheel deltas in lines/pages | Zoom treated the numbers as pixels | Units are normalized before applying zoom |
| Notebook move and release arrive before a paint | Saved the previous notebook dimensions | Final paint flushes before persistence |

Stage gestures now have one pointer-ownership implementation in
`lab/stage-gestures.js`. Camera and physics calculations remain in their existing
owners. Pinches and drags that return to their start cannot masquerade as taps;
blur, page hiding, cancellation and lost capture clear active gestures. Undo holds
track pointer IDs and ignore duplicate or unrelated releases.

`lab/frame-coalescer.js` replaces the separate notebook and rack painting mechanisms.
It retains the rack's 32 ms fallback when animation frames stall, flushes on release,
and leaves no pending callbacks after a flush. A deterministic test posts 40 moves
and measures one application of the final value. This is a scheduling guarantee,
not a claim of higher GPU throughput or measured phone battery life.

The package explicitly declares ES modules, eliminating Node's repeated format
detection warnings. The prebuilt UMD vendor scripts have a CommonJS package boundary
so KaTeX still loads correctly in the notebook safety tests. No dependency was added.
README/contribution links and module descriptions were corrected. Offline hashes
were regenerated to include the new modules.

## Validation

- `npm test`: all 67 Node suites, including physics, gestures, batching and offline integrity.
- `npm run test:browser`: all six current Firefox suites, including GPU and molecular-field checks.
- The input suite additionally uses real WebDriver mouse and touch drags, and checks
  phone portrait (500×844), phone landscape (844×390), and desktop (1280×814).
- `npm run build`: assembled site and asset references verified.
- `git diff --check` and syntax checks for changed application modules.

Environment: Node 22.22.1, Firefox 154.0.1 on Linux. Firefox's headless window has a
500 px minimum width: portrait coverage is not a physical 390 px phone test. Actual
iPhone/iPad Safari, Android Chrome, screen readers and sustained device performance
still require their own acceptance pass. The standalone input suite covers injected
cancellation events as well as real mouse/touch capture; these are distinct checks.

## Remaining repository findings

1. **MIR provenance: resolved in the follow-up.** The original review found
   `lab/mir/kit.js` behind MIR 1.1.3 and no `MIR-MANIFEST.json`. Re-adoption from
   MIR commit `05155da7e5ca0d2a85383242722db1b84a774e1f` restored the 29-file
   manifest and the adoption check now reports "in step". A new Node gate verifies
   every adopted file against that inventory without needing the MIR checkout.
   Browser checks preserve default knob/fader sensitivity and keyboard steps,
   and verify the upstream opt-in sensitivity and logarithmic/modulated faders.
2. **The rack is still too coupled.** It remains about 5,900 lines, with project
   restore, notebook editing, window layout, controls and rendering orchestration
   in one boot closure. The next useful extraction is project snapshot/restore as
   one cohesive interface, backed by existing persistence/browser tests. Splitting
   arbitrary line ranges would only move the coupling around.
3. **Device claims need measured hardware results.** The automated gates are useful
   regression checks, but the release device matrix in shipping readiness remains
   the place to record real hardware, browser versions and sustained frame rates.
